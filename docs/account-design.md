# Account website design

The account website extends the Ultra Tasks app's design language. It uses the same system font stack, 4/8px spacing scale, 10px control/card corners, flat bordered surfaces, and default teal accent. `apps/account/public/account-theme.css` snapshots the app's normalized default palette from client commit `b79c0f94d5`, including accessible text, border, focus, and selected-state roles. Update both modes when those defaults change. The logo is copied from the client's `src/assets/ultra-tasks/logo.svg`; it retains the project's existing license.

The website follows the operating system's light/dark preference. The app's account screen inherits the app's active theme, including user customizations, and uses its shared Material controls. The website has no font CDN, tracking, or new UI framework dependency.

Sign-in, account creation, email verification, and recovery are separate views. Signup still requires saving the vault recovery key before registration; returning to account details discards the prepared key and creates a new one on the next attempt. MFA replaces the password form and offers enrolled methods only. Recovery links retain their existing secret-removal behavior. A settings sidebar separates Overview, Security, Profile, and Devices; on phones it becomes a wrapping row. Overview uses the server's actual encrypted-byte quota for its storage meter. Destructive actions remain under an explicit disclosure and confirmation.

`scripts/install-dashboard.mjs` installs the theme, logo, and portal into both the inherited public directory and the private-only account directory used by the production image. Run `npm run quiet -- build:dashboard` after editing account assets.

Browser coverage exercises real registration, recovery-key export, verification, security-key enrollment/login, recovery, offline unlocking, device approval, deletion, navigation, and mobile light/dark layouts. The Better Auth browser suite can capture the real Windows Electron app using `ULTRA_ELECTRON_EXECUTABLE` and `ULTRA_ELECTRON_APP`, with `ULTRA_CLIENT_DIST` pointing to a current independent app build and `ULTRA_AUTH_SCREENSHOTS` pointing to an output directory. Test accounts and app profiles are isolated from personal data.

The fresh-context review fixed a missing return path from signup recovery-key preparation and missing top-level headings on standalone account steps. No actionable findings remained. Account Chromium acceptance passed all 3 tests; Better Auth UI acceptance passed all 3 tests, including real Windows Electron sign-in, MFA cancellation/retry, and personal-data linking. Server/package builds, dashboard typecheck, and formatting checks passed. These are local UI acceptance results, not a hosted deployment or a cryptographic audit.
